## Exact arithmetic versus baseline display

The old independent oracle rounded exact decimal charge differences using decimal half-up arithmetic and compared them directly with production output. Production uses JavaScript Number arithmetic followed by `toFixed(1)`. These policies disagree at some halfway values. This is a **test-oracle policy mismatch**, not evidence authorizing a production rounding change.

## Independent checks

- [Numerical references](../../tests/helpers/abg-numerical-reference.js) parse finite decimal/exponent inputs as integer fractions. Charge difference is evaluated exactly and checked against literal precomputed values.
- The VM test observes the raw Number passed to the existing one-decimal formatter and delegates unchanged to its original implementation. No formula is patched, exported, or bypassed. Valid calculations must produce exactly one observation; invalid calculations must produce none.
- Raw arithmetic is compared using exact rational representations of binary64 values and a conservative absolute engineering allowance of `8 × Number.EPSILON × max(|Na|, |Cl|, |HCO₃|)`. This covers input conversion and arithmetic error at the tested operand scales. It is neither a clinical tolerance nor permission to change thresholds.
- Display and selected binary values have separate literal baseline snapshots. Expectations are not generated by running the production formula during the tests.
- A sensitivity check rejects a 0.001 raw error even though the one-decimal display remains unchanged. This prevents formatted output alone from hiding arithmetic regressions.
- [Existing independent fixtures](../../tests/abg-independent-fixtures-test.js) retain E1–E9, all 30 primary-label boundaries and Winter checks; the exact-decimal display oracle is replaced with raw mathematical checks plus explicit current-display snapshots.
- [Additional regressions](../../tests/abg-anion-gap-numerical-test.js) cover halfway values, binary neighbors, negative/zero/tiny gaps, supported extrema, all six fields with invalid/non-finite/extreme inputs, exact input bounds and their immediate exterior binary neighbors, failure clearing and corrected recalculation.

## Domain and limitations

Current input validation bounds the mathematical gap to −160 through 179. Very large finite gap outputs, subnormal gap inputs, and overflow are not supported calculator scenarios. References at `1e308` and `5e-324` exercise only the exact test oracle; production receives those values solely in rejection tests. No validation is bypassed to manufacture unsupported production outputs. `1e309` tests overflow to Infinity; `1e-324` tests conversion underflow to zero, followed by rejection.

The snapshots establish regression behavior, not clinical plausibility. Tests do not approve mixed-disorder labels, physiologic consistency, gap interpretation, or numerical precision. The VM observation relies on the current formatting call; a future formatting refactor must update the observation mechanism explicitly rather than silently dropping the mathematical checks.
